    Подготовка

    За час до собеса¶

    Шпаргалки всех страниц на одной: прочитай разделы своего стека сверху вниз и проговори каждую строку вслух. Таблицы подключаются из самих страниц, поэтому здесь всегда та же версия, что и в полном разборе.

    Как повторять

    Строка не вспоминается за пару секунд — открой полный разбор и прочитай «Ответ вслух» этой темы. Новое за час до собеса не учи: только освежай то, что уже разбирал.

    Java¶

    Основы языка¶

    Полный разбор →

    Тема Запомнить
    Примитивы 8 типов, хранят значение, не бывают null; ссылочные хранят адрес объекта в куче
    Передача параметров Только по значению; для объектов копируется ссылка
    Автоупаковка Компилятор вставляет valueOf() и intValue(); появилась в Java 5
    Ловушки автоупаковки Распаковка null → NPE; Integer Cache -128..127 — сравнивай через equals(); обёртки в цикле — лишние объекты
    equals() / hashCode() Равны по equals → равны хэши; без hashCode() ломаются HashMap и HashSet
    final / finally / finalize() Запрет изменений / блок после try / устаревший метод GC
    static Принадлежит классу; статические методы не переопределяются, а скрываются
    Порядок инициализации static родителя → static наследника → поля и блоки родителя → конструктор родителя → то же для наследника
    Значения по умолчанию У полей и элементов массивов — нули, false, null; у локальных переменных — нет
    enum final-класс, наследник Enum; values() и valueOf() от компилятора; EnumSet / EnumMap; не храни ordinal()
    Модификаторы доступа private → default → protected → public; protected из другого пакета — только через наследование

    Строки¶

    Полный разбор →

    Тема Запомнить
    Неизменяемость String Любая «модификация» создаёт новый объект; причины — безопасность, потоки, String Pool
    StringBuilder Изменяемый, без синхронизации, массив растёт вдвое + 2 — выбор по умолчанию для сборки текста
    StringBuffer То же, но synchronized — только легаси
    a + b + c С Java 9 — invokedynamic + StringConcatFactory; в цикле всё равно StringBuilder
    String Pool Один экземпляр каждого литерала, в куче с Java 7; new String() пул обходит
    == для строк Сравнивает ссылки; содержимое — только через equals()
    intern() Вернуть строку из пула или положить её туда; полезен, когда одинаковых строк много

    ООП¶

    Полный разбор →

    Тема Запомнить
    ООП Объекты объединяют данные и логику; цель — управлять сложностью
    Инкапсуляция Защита инвариантов через бизнес-методы, а не геттеры и сеттеры
    Абстракция Важно ЧТО, а не КАК; интерфейсы и абстрактные классы
    Полиморфизм Overload — компилятор, override — JVM по реальному типу
    Интерфейс vs абстрактный класс CAN-DO vs IS-A; у интерфейса нет состояния и конструкторов
    default / static / private Совместимость (Java 8) / утилиты (Java 8) / общий код (Java 9)
    Сигнатура Имя + параметры; возвращаемый тип и throws не входят
    Ковариантность При override можно сузить возвращаемый тип до подтипа

    Исключения¶

    Полный разбор →

    Тема Запомнить
    Иерархия Throwable → Error (не трогаем) и Exception (обрабатываем)
    Checked Наследники Exception кроме RuntimeException; компилятор требует catch или throws
    Unchecked Наследники RuntimeException; обычно баги в логике
    SQLException Checked, наследует Exception напрямую, а не IOException
    Порядок catch Сначала частные, потом общие; multi-catch A \| B с Java 7
    finally Не выполнится при System.exit, смерти процесса, бесконечном try; при OOM — выполнится
    return в finally Проглатывает исключение из try — так не пишут
    try-with-resources AutoCloseable, закрытие в обратном порядке, suppressed-исключения
    Свои исключения Доменный смысл и контекст; в Spring — unchecked
    Антипаттерны Пустой catch, лог + проброс, ловля Exception без причины, потерянный cause
    Spring @RestControllerAdvice и @ExceptionHandler — в Spring MVC

    Дженерики¶

    Полный разбор →

    Тема Запомнить
    Зачем дженерики Проверка типов при компиляции, без ручных кастов
    Type erasure JVM не знает о дженериках: List<String> и List<Integer> в байт-коде одинаковы
    Bridge-метод Компилятор генерирует его для сохранения полиморфизма; виден через javap -p
    ? extends T Читать можно, писать нельзя — producer
    ? super T Писать можно, читать только как Object — consumer
    List<?> vs List<Object> Любой список, но без записи vs конкретный тип с записью, но инвариантный
    PECS Producer Extends, Consumer Super — правило Джошуа Блоха
    Bounds <T extends A & B> — класс первым, интерфейсы потом
    Запреты Нет new T(), new T[], List<int>, static T — всё из-за стирания
    Raw types Дженерик без <T> отключает проверку типов — красный флаг на ревью
    Heap pollution Дженерик-переменная ссылается на несовместимый объект → ClassCastException при чтении
    @SafeVarargs Только если varargs-массив не уходит наружу; только static, final, private

    Современная Java¶

    Полный разбор →

    Тема Запомнить
    var Java 10, только локальные переменные с инициализатором; тип фиксируется при компиляции
    record Java 16, final-класс с private final полями, equals / hashCode / toString и аксессорами без get; валидация — в компактном конструкторе
    switch-выражение Java 14, -> без проваливания, yield для многострочных веток, должен покрывать все варианты
    Pattern matching instanceof с переменной — Java 16; паттерны в switch и record-паттерны — Java 21; общий тип не выше частного
    sealed Java 17, наследники только из permits; каждый — final, sealed или non-sealed
    sealed + switch Исчерпывающий switch без default; новый вариант ломает компиляцию, а не прод

    Коллекции¶

    Полный разбор →

    Тема Запомнить
    Иерархия Iterable → Collection → List / Set / Queue. Map отдельно (Interface Segregation)
    Queue offer / poll / peek возвращают false / null; add / remove / element бросают исключение
    ArrayList Массив Object[], ёмкость 10 → 15 → 22 → 33 (×1,5), get — O(1)
    LinkedList Двусвязный список, доступ по индексу O(n), плохая cache locality — почти не используется
    Вставка в середину ArrayList обычно быстрее: LinkedList тратит O(n) на поиск узла
    HashSet Обёртка над HashMap, элемент — ключ, значение — PRESENT
    TreeSet Красно-чёрное дерево, O(log n); нужен Comparable или Comparator; дубликаты — по compare() == 0
    Comparable vs Comparator Естественный порядок в классе vs внешняя стратегия; сравнивай через Integer.compare
    Стек и очередь ArrayDeque, не Stack; null не принимает
    PriorityQueue Двоичная куча: peek O(1), offer / poll O(log n); порядок только через poll()
    CME modCount против expectedModCount; удаляй через removeIf или iterator.remove()

    HashMap¶

    Полный разбор →

    Тема Запомнить
    HashMap 16 бакетов, индекс (n - 1) & hash, ёмкость — степень двойки
    Коллизии Цепочка в бакете; с Java 8 — дерево при 8+ узлах и 64+ бакетах, обратно при ≤ 6
    Rehashing Порог capacity × 0.75; расширение ×2 за O(n). Размер заранее — HashMap.newHashMap(n)
    LinkedHashMap / TreeMap Порядок добавления или доступа (LRU) / сортировка по ключу за O(log n)

    Stream API¶

    Полный разбор →

    Тема Запомнить
    Stream Не структура данных, а конвейер: источник → промежуточные → терминальная
    Ленивость Промежуточные операции не выполняются без терминальной; стрим одноразовый
    map / flatMap Один к одному / один ко многим со склейкой
    Порядок Вертикально: элемент проходит весь конвейер; filter — пораньше
    Short-circuiting limit, takeWhile, anyMatch, findFirst, findAny
    Примитивные стримы IntStream и др.: без упаковки, есть sum, average, summaryStatistics
    parallelStream() Только для больших CPU-bound задач без общего состояния и после замера; общий commonPool()
    Сбор в коллекцию toUnmodifiableList() — Java 10, stream.toList() — Java 16, оба неизменяемы
    toMap Дубликат ключа → IllegalStateException; null в значении → NPE
    Группировка groupingBy + downstream; partitioningBy — всегда два ключа

    Лямбды и Optional¶

    Полный разбор →

    Тема Запомнить
    Функциональные интерфейсы Один абстрактный метод; Predicate, Function, Consumer, Supplier
    Effectively final Лямбда захватывает копию значения — переменная не должна меняться

    IO / NIO¶

    Полный разбор →

    Задача Рекомендуемый способ
    Прочитать небольшой текстовый файл целиком Files.readString(path, UTF_8)
    Прочитать небольшой файл построчно в список Files.readAllLines(path, UTF_8)
    Обработать большой файл построчно Files.lines(path) в try-with-resources
    Прочитать бинарный файл Files.readAllBytes(path)
    Записать строку в файл Files.writeString(path, text, UTF_8)
    Дозаписать в файл Files.writeString(path, text, UTF_8, APPEND, CREATE)
    Копировать файл Files.copy(src, dest, REPLACE_EXISTING)
    Создать директории рекурсивно Files.createDirectories(path)
    Обойти директорию рекурсивно Files.walk(path) в try-with-resources
    Работа с кастомной логикой парсинга Files.newBufferedReader(path, UTF_8)
    Построчная запись Files.newBufferedWriter(path, UTF_8)
    Байты против символов InputStream/OutputStream — бинарное, Reader/Writer — текст
    Кодировка Всегда явно StandardCharsets.UTF_8; по умолчанию UTF-8 только с Java 18

    Правило большого пальца

    Если нужна простая операция — Files.*. Если нужен контроль над буфером, кодировкой или построчной обработкой — Files.newBufferedReader / Files.newBufferedWriter. FileInputStream/FileOutputStream напрямую — только для бинарных данных или совместимости со старым кодом.

    Память и сборка мусора¶

    Полный разбор →

    Тема Запомнить
    JVM / JRE / JDK JVM выполняет байт-код; JRE = JVM + библиотеки; JDK = JRE + javac и утилиты
    GC Roots Стеки потоков, статические поля, активные потоки; недостижимое — мусор, циклы не мешают
    Поколения Eden → Survivor → Old; Minor GC часто и быстро, Major/Full GC — редко и дорого
    Mark-Sweep-Compact Пометить живые → освободить остальное → убрать фрагментацию
    Stop-The-World Пауза всех потоков приложения; эволюция GC — борьба за короткие паузы
    Сборщики Serial, Parallel, G1 (по умолчанию с Java 9), ZGC и Shenandoah (паузы не зависят от размера кучи)
    Stack vs Heap Стек — свой у потока, фреймы и ссылки, -Xss; куча — общая, объекты, -Xmx
    Metaspace Метаданные классов вне кучи, с Java 8 вместо PermGen; ограничивай -XX:MaxMetaspaceSize
    Статика и String Pool В куче: пул — с Java 7, статические поля — с Java 8
    OOM Error, а не Exception; виды: heap space, GC overhead, Metaspace, native thread
    Расследование OOM -XX:+HeapDumpOnOutOfMemoryError → Eclipse MAT → чинить код → и только потом -Xmx

    Многопоточность¶

    Потоки и ThreadLocal¶

    Полный разбор →

    Тема Запомнить
    Процесс vs поток У процесса своя память; потоки процесса делят кучу, но у каждого свой стек
    Thread vs Runnable Задача — в Runnable (или Callable), запуск — в Thread или пуле; extends Thread — моветон
    Жизненный цикл NEW → RUNNABLE → BLOCKED / WAITING / TIMED_WAITING → TERMINATED; перезапустить нельзя
    sleep / join / yield sleep не отпускает мониторы; join ждёт завершения потока; yield — лишь подсказка
    Остановка потока interrupt() + проверка флага; в catch (InterruptedException) восстанавливай флаг
    ThreadLocal Значение — в ThreadLocalMap потока, ключ слабый, значение — нет; в пуле — remove() в finally; InheritableThreadLocal копирует только при создании потока, в пул контекст переносит TaskDecorator

    Блокировки и синхронизаторы¶

    Полный разбор →

    Тема Запомнить
    synchronized Монитор объекта: атомарность и видимость; static synchronized — монитор класса
    wait / notify Только внутри synchronized; ждать в while, а не в if (spurious wakeup)
    ReentrantLock tryLock, прерываемое ожидание, fairness, несколько Condition; unlock() — в finally
    ReadWriteLock / StampedLock Много читателей или один писатель; StampedLock — оптимистичное чтение со stamp
    Синхронизаторы CountDownLatch — одноразовый, CyclicBarrier — многоразовый, Semaphore — ограничение доступа
    AQS volatile int state + очередь ожидания; основа ReentrantLock, Semaphore, CountDownLatch
    park / unpark Пермит на поток; unpark() до park() не теряется, в отличие от notify()

    JMM, volatile и атомики¶

    Полный разбор →

    Тема Запомнить
    JMM Атомарность, видимость, упорядочивание; без happens-before — data race
    volatile Видимость и запрет переупорядочивания через барьеры; count++ не делает атомарным
    final-поля Видны всем потокам после конструктора, если this не утёк
    Atomics CAS без блокировок; под высокой конкуренцией счётчики — LongAdder

    LRU vs LFU LRU — давно не трогали. LFU — мало раз трогали
    Cache stampede Толпа на истёкший TTL. Лечить mutex-локом или ранним обновлением
    Очереди Point-to-point — один consumer, pub/sub — все. Битые сообщения — в DLQ
    CDN Edge рядом с пользователем: единицы мс вместо ~150 мс. Pull — дефолт

    Распределённые данные¶

    Полный разбор →

    Тема Запомнить
    Replication Master пишет, реплики читают. Replication lag → read-your-writes с master
    Partitioning Один сервер. Горизонтальное (строки) / вертикальное (столбцы)
    Sharding Много серверов. Боль: джоины, распределённые транзакции, ребаланс. Hotspot от «звёзд»
    Consistent hashing Кольцо: новый узел двигает только соседний участок. Виртуальные узлы для равномерности
    CAP Сеть рвётся всегда → выбор C vs A в аварию. CP — деньги (HBase, ZooKeeper), AP — корзина и закладки (Cassandra, DynamoDB); CA — только один сервер
    PACELC Без аварии — выбор между latency и consistency. Cassandra: ConsistencyLevel на запрос
    Модели согласованности Strong → causal → read-your-writes → monotonic → eventual. Бери минимально достаточную
    Консенсус Кворум N/2+1, кластеры нечётные (3/5); Raft — etcd/Consul/KRaft, ZAB — ZooKeeper

    DDD, CQRS и Event Sourcing¶

    Полный разбор →

    Тема Запомнить
    Ubiquitous Language Бизнес-термин = класс = таблица. Код читается как спецификация
    Bounded Context Одна сущность — разные модели в разных контекстах. Часто = микросервис
    Context Mapping / ACL ACL — прослойка-переводчик на границе: легаси или чужая модель не протекает в домен
    Aggregate Root Изменения только через корень (order.addItem()). Защита инвариантов
    Anemic vs Rich Логика — в домене, а не в сервисах-простынях с геттерами и сеттерами
    Value Object Без ID, неизменяемый. Money, record. Защита от ошибок на уровне типов
    Domain Event Событие в прошедшем времени. Развязывает контексты; наружу — через Outbox
    CQRS Разные модели для Command и Query. Read-реплики — CQRS на минималках
    Eventual Consistency Write и Read модели рассинхронизированы на доли секунды — главный подвох CQRS
    Event Sourcing История событий (append-only), состояние = replay. 100% аудит, машина времени
    Snapshot / Upcasting Snapshot — против медленного replay. Upcasting — против версий событий

    Микросервисы и отказоустойчивость¶

    Полный разбор →

    Тема Запомнить
    Монолит vs микросервисы Начинай с монолита; distributed monolith — худший исход

    Circuit breaker Closed → Open → Half-Open. Fail fast против каскадного отказа
    Bulkhead Изолируй пулы потоков по зависимостям; fallback — урезанный ответ вместо 500

    Computer Science¶

    Big O и структуры данных¶

    Полный разбор →

    Тема Запомнить
    Big O Рост времени или памяти при росте N; худший случай; O(1) < O(log N) < O(N) < O(N log N) < O(N²)
    Упрощение Константы отбрасываем, оставляем доминирующий член, O(N + M) не упрощаем
    Память Рекурсия глубины N — O(N) на стеке
    Массив vs список Массив: доступ O(1), вставка в середину O(N). Список: доступ O(N), вставка у узла O(1)
    HashMap / HashSet O(1) в среднем, O(N) в худшем при коллизиях
    Стек и очередь ArrayDeque: push/pop и offer/poll за O(1)
    PriorityQueue Min-heap: peek O(1), offer/poll O(log N); компаратор — через Integer.compare
    BST O(log N) в среднем, O(N) у вырожденного; inorder — отсортированный порядок
    BFS по дереву Очередь + размер уровня, сохранённый до цикла
    Красно-чёрное дерево O(log N) гарантированно; TreeMap, TreeSet, бакеты HashMap с Java 8

    Сортировки и графы¶

    Полный разбор →

    Тема Запомнить
    Сортировки O(N log N): Merge, Quick (в среднем), Heap, Tim. Java: Tim Sort для объектов, Quick Sort для примитивов
    Merge Sort Делим пополам, сливаем за O(N); стабильна, O(N) памяти
    Quick Sort Partition вокруг pivot; O(N²) на отсортированном с крайним pivot → случайный pivot
    Граф Список смежности — по умолчанию, матрица — для плотных
    BFS по графу Кратчайший путь без весов; помечать при добавлении в очередь
    DFS Рекурсия или стек; глубокий граф — итеративно
    Дейкстра Min-куча + релаксация, O((V + E) log V), без отрицательных весов

    TCP/IP, HTTP и TLS¶

    Полный разбор →

    Тема Запомнить
    OSI и TCP/IP 7 уровней против 4; бэкенд живёт на транспортном (TCP/UDP) и прикладном (HTTP, DNS)
    TCP vs UDP TCP: соединение, доставка, порядок, целостность. UDP: без гарантий, минимальная задержка
    TCP handshake SYN → SYN-ACK → ACK, 3 пакета до данных; закрытие — FIN/ACK с каждой стороны
    QUIC Надёжность поверх UDP, отдельно для каждого потока; TLS 1.3 встроен
    HTTP Запрос → ответ поверх TCP, stateless: состояние в куках, токенах, Redis
    HTTP/1.1 → 2 → 3 1.1 — keep-alive, но по очереди. 2 — мультиплексирование, HOL в TCP. 3 — QUIC, HOL убран
    401 vs 403 401 — не аутентифицирован. 403 — аутентифицирован, но нет прав
    Идемпотентность GET, PUT, DELETE, HEAD, OPTIONS — идемпотентны. POST — нет, PATCH — зависит
    TLS Конфиденциальность, целостность, аутентификация. 1.2 — 2 RTT, 1.3 — 1 RTT
    Сертификаты Цепочка до Root CA из ОС + совпадение домена + срок действия
    Ввод URL DNS → TCP → TLS → HTTP → рендеринг; лечат кэш DNS, keep-alive, пул соединений, CDN
    DNS Кэш → резолвер → Root → TLD → Authoritative; кэш на TTL; geo-DNS — грубая балансировка
    DNS-записи A / AAAA — IP, CNAME — псевдоним, MX — почта, TXT — текст, SRV — сервис + порт
