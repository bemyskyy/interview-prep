# Современная Java

Что появилось в языке после Java 8 и что спрашивают про это на собесах: `var`, `record`, новый `switch`, pattern matching и `sealed`-классы. Чаще всего спрашивают, делает ли `var` Java динамической, может ли `record` наследоваться и зачем `sealed` нужен в паре со `switch`.

## Синтаксис { #syntax }

### Что такое `var` и где его нельзя использовать? { #var }

**Уровень:** Junior

!!! abstract "Ответ вслух"
    `var` (Java 10) — вывод типа локальной переменной: компилятор берёт тип из правой части присваивания, а Java остаётся строго типизированной. Работает только для локальных переменных с инициализатором — в методах, циклах `for` и `try-with-resources`. Для полей, параметров методов и возвращаемых типов `var` нельзя.

Многие, кто пришёл из JavaScript или Python, думают, что с `var` Java стала динамически типизированной. Это главная ловушка.

- **Как это работает:** `var` — синтаксический сахар для компилятора. Компилятор сам выводит тип переменной по значению справа от `=`, и дальше тип не меняется.
- **Где можно:** **только локальные переменные** внутри методов, в циклах `for` и в `try-with-resources`. С Java 11 — ещё и параметры лямбд: `(var x, var y) -> x + y`.
- **Где нельзя (ошибки компиляции):**
    - поля класса — тип поля должен быть известен до создания объекта;
    - параметры методов и возвращаемые типы;
    - `var x;` без инициализации — компилятору не за что зацепиться;
    - `var str = null;` — у `null` нет конкретного типа.

```java
Map<String, List<User>> before = new HashMap<>(); // было
var after = new HashMap<String, List<User>>();      // стало: тип выведен из правой части

for (var entry : after.entrySet()) {                // ✅ в цикле
    System.out.println(entry.getKey());
}

var count = 10;
// count = "десять";  // ❌ ошибка компиляции: тип count уже int
// var x;             // ❌ ошибка компиляции: нет инициализатора
// var y = null;      // ❌ ошибка компиляции: тип null не определён
```

!!! warning "Ловушка: «`var` делает Java динамической»"
    Тип переменной с `var` фиксируется при компиляции и больше не меняется: `var count = 10; count = "десять";` не скомпилируется. `var` экономит только текст, а не проверки типов.

### Что такое `record`? { #records }

**Уровень:** Junior

!!! abstract "Ответ вслух"
    `record` (финальная версия — Java 16) — класс-носитель данных: одна строчка даёт `final`-класс с `private final` полями, конструктором, `equals()`, `hashCode()`, `toString()` и аксессорами без префикса `get`. От других классов он наследоваться не может — уже наследует `java.lang.Record`, — но интерфейсы реализует. Проверку данных пишут в компактном конструкторе.

Одно из самых важных нововведений для работы с данными. `record` — специальный вид класса для одной цели: быть прозрачным и неизменяемым носителем данных (DTO, сообщения для Kafka, ответы API).

- **Как это работает:** пишешь одну строчку: `public record UserDto(Long id, String name) {}`
- **Что делает компилятор:**
    1. Создаёт `final`-класс (от него нельзя наследоваться).
    2. Делает все поля `private final`.
    3. Генерирует конструктор со всеми аргументами.
    4. Генерирует `equals()`, `hashCode()` и `toString()` по всем компонентам.
    5. Генерирует аксессоры **без префикса `get`**: `id()` и `name()`.

```java
public record UserDto(Long id, String name) {

    // Компактный конструктор: без списка параметров, присваивания компилятор допишет сам
    public UserDto {
        if (id == null || id < 0) {
            throw new IllegalArgumentException("id должен быть положительным");
        }
    }
}

UserDto user = new UserDto(1L, "Alice");
System.out.println(user.name()); // Alice — не getName()
System.out.println(user);        // UserDto[id=1, name=Alice]
```

Вопросы на собесе:

- _"Может ли record наследоваться от другого класса?"_ — **Нет**: он уже неявно наследует `java.lang.Record`.
- _"Может ли реализовывать интерфейсы?"_ — **Да**, сколько угодно.
- _"Можно ли добавить валидацию?"_ — **Да**, в компактном конструкторе: проверка выполняется до того, как значения запишутся в поля.

!!! warning "Ловушка: неизменяемость `record` — поверхностная"
    Поля `record` нельзя переприсвоить, но объекты внутри них можно менять. `record Team(List<String> members)` с обычным `ArrayList` позволит сделать `team.members().add(...)`. Делай защитную копию в компактном конструкторе: `members = List.copyOf(members);`.

### Как работает новый `switch`? { #switch-expressions }

**Уровень:** Junior

!!! abstract "Ответ вслух"
    Со стрелкой `->` нет проваливания в следующий `case`, и `break` не нужен. `switch` стал выражением (Java 14): он возвращает значение прямо в переменную, а из многострочной ветки значение отдают через `yield`. Выражение `switch` обязано покрывать все варианты.

Старый `switch` с вечными `break` был источником тысяч багов: забыл `break` — выполнение «провалилось» в следующий `case`. Современная Java переосмыслила этот оператор (Java 12–14, финальная версия — Java 14).

- **Стрелочный `switch`:** вместо двоеточия — стрелка `->`. Главный плюс — **нет проваливания (fall-through)**: отрабатывает ровно одна ветка, `break` не нужен.
- **`switch` как выражение (expression):** может **возвращать значение** прямо в переменную.
- **`yield`:** если ветка сложная и занимает несколько строк (в фигурных скобках), значение из неё возвращают через `yield`, а не `return`.

```java
String type = switch (day) {
    case MONDAY, FRIDAY -> "Рабочий";
    case SATURDAY, SUNDAY -> "Выходной";
    default -> "Неизвестно";
};

int bonus = switch (day) {
    case SATURDAY, SUNDAY -> {
        int base = 100;
        yield base * 2;   // yield возвращает значение из блока
    }
    default -> 0;
};
```

!!! warning "Ловушка: выражение `switch` должно быть исчерпывающим"
    Если `switch` возвращает значение, компилятор требует покрыть все варианты. Для `enum`, где перечислены все константы, или для `sealed`-иерархии `default` не нужен; для `String` или `int` без `default` код не скомпилируется.

    2. Как вернуть значение из многострочной ветки `switch`-выражения?

### Что такое pattern matching? { #pattern-matching }

**Уровень:** Middle

!!! abstract "Ответ вслух"
    Это проверка типа с одновременным извлечением значения. В `instanceof` (Java 16) переменная нужного типа объявляется прямо в условии, без ручного приведения. В `switch` (Java 21) можно разбирать любые объекты по типам, а record-паттерны сразу достают компоненты записи.

- **Pattern matching для `instanceof` (Java 16):** раньше писали `if (obj instanceof String) { String s = (String) obj; s.length(); }`. Теперь приведение происходит прямо в условии: `if (obj instanceof String s) { s.length(); }`.
- **Pattern matching для `switch` (Java 21):** в `switch` можно передавать не только числа, строки и `enum`, но и **любые объекты**, проверяя их типы. Условие уточняют через `when`.
- **Record-паттерны (Java 21):** `case Point(int x, int y)` проверяет тип и сразу раскладывает запись на компоненты.

```java
static String describe(Object obj) {
    if (obj instanceof String s && !s.isBlank()) { // s уже String, приведение не нужно
        return "Непустая строка: " + s;
    }
    return switch (obj) {
        case String s -> "Строка: " + s;                 // сюда попадут пустые строки
        case Integer i when i > 0 -> "Положительное число: " + i;
        case Integer i -> "Число: " + i;
        case UserDto u -> "Пользователь: " + u.name();
        case Point(int x, int y) -> "Точка " + x + ", " + y; // record-паттерн
        default -> "Что-то другое";
    };
}

record Point(int x, int y) {}
```

!!! warning "Ловушка: порядок веток с типами"
    Более общий тип не может стоять выше более частного: `case CharSequence cs` перед `case String s` — ошибка компиляции, потому что вторая ветка никогда не сработает. То же с `case Integer i` перед `case Integer i when i > 0`.

## Иерархии типов { #hierarchies }

### Что такое `sealed`-классы? { #sealed }

**Уровень:** Middle

!!! abstract "Ответ вслух"
    `sealed` (Java 17) разрешает наследоваться только перечисленным в `permits` классам — промежуточный вариант между открытым классом и `final`. Каждый разрешённый наследник обязан быть `final`, `sealed` или `non-sealed`. Так в доменной модели фиксируют закрытый набор вариантов.

До `sealed` было две крайности: класс открыт для наследования всем подряд (обычный класс) или закрыт для всех (`final`). `sealed` даёт середину: наследоваться можно, но **только строго определённому списку классов**.

**Как это работает:** класс или интерфейс объявляется с ключевым словом `sealed`, а в `permits` явно перечисляются те, кто имеет право от него наследоваться.

```java
public sealed interface PaymentResult permits Success, Failure, Pending {
}

// Наследниками могут быть обычные классы или record'ы
public record Success(String receiptId) implements PaymentResult {}
public record Failure(String errorMessage) implements PaymentResult {} // не Error: имя совпало бы с java.lang.Error
public record Pending(String transactionId) implements PaymentResult {}
```

**Зачем это нужно:** инструмент для Domain-Driven Design. В модуле оплат результат может быть только трёх видов: успех, ошибка или ожидание. `sealed` физически запрещает другим разработчикам добавить свой `class Timeout implements PaymentResult`, который сломает обработку.

Интервьюер спросит: _"Какие правила обязаны соблюдать наследники запечатанного класса?"_ Их три:

1. **Известны при компиляции:** все классы из `permits` должны быть видны компилятору и лежать в том же модуле, а без модулей — в том же пакете. Если наследники объявлены в том же файле, `permits` можно не писать.
2. **Прямое наследование:** наследник обязан напрямую расширять (`extends`) или реализовывать (`implements`) `sealed`-тип.
3. **Обязательный модификатор:** каждый разрешённый наследник выбирает дальнейшую судьбу иерархии:
    - `final` — иерархия закрывается (дальше наследоваться нельзя). Эту роль хорошо выполняют `record` — они `final` по умолчанию.
    - `sealed` — наследник тоже запечатан и перечисляет своих разрешённых потомков через `permits`.
    - `non-sealed` (через дефис) — наследник снова открывает иерархию для всех.

!!! warning "Ловушка: наследник без модификатора"
    Если класс из `permits` объявить просто `class Success implements PaymentResult`, без `final`, `sealed` или `non-sealed`, код не скомпилируется. У `record` модификатор `final` уже есть неявно.

### Зачем `sealed` нужен в паре со `switch`? { #sealed-switch }

**Уровень:** Senior

!!! abstract "Ответ вслух"
    Компилятор знает всех наследников `sealed`-типа, поэтому `switch` по нему можно написать без `default`. Если кто-то добавит новый вариант в `permits`, каждый такой `switch` перестанет компилироваться, пока его не обработают. Ошибка ловится на сборке, а не в продакшене.

Главная сила `sealed` раскрывается вместе с новым `switch`. Если прогнать `sealed`-тип через `switch`, компилятор **знает все варианты наследников** — блок `default` **больше не нужен**.

```java
static String message(PaymentResult result) {
    // Компилятор видит, что перебраны все 3 разрешённых варианта — default не нужен
    return switch (result) {
        case Success s -> "Оплачено: " + s.receiptId();
        case Failure f -> "Ошибка: " + f.errorMessage();
        case Pending p -> "В обработке: " + p.transactionId();
    };
}
```

_Профит:_ если завтра кто-то добавит новый статус `Refunded` в `permits`, код не скомпилируется, пока не добавишь обработку нового варианта в `switch`. Никаких скрытых багов в рантайме.

!!! warning "Ловушка: `default` убивает проверку"
    Если «на всякий случай» добавить `default` в `switch` по `sealed`-типу, компилятор перестанет требовать обработку новых вариантов: `Refunded` молча уйдёт в `default`. Для `sealed`-иерархий `default` лучше не писать.

## Шпаргалка { #cheatsheet }

| Тема | Запомнить |
|---|---|
| **`var`** | Java 10, только локальные переменные с инициализатором; тип фиксируется при компиляции |
| **`record`** | Java 16, `final`-класс с `private final` полями, `equals` / `hashCode` / `toString` и аксессорами без `get`; валидация — в компактном конструкторе |
| **`switch`-выражение** | Java 14, `->` без проваливания, `yield` для многострочных веток, должен покрывать все варианты |
| **Pattern matching** | `instanceof` с переменной — Java 16; паттерны в `switch` и record-паттерны — Java 21; общий тип не выше частного |
| **`sealed`** | Java 17, наследники только из `permits`; каждый — `final`, `sealed` или `non-sealed` |
| **`sealed` + `switch`** | Исчерпывающий `switch` без `default`; новый вариант ломает компиляцию, а не прод |
