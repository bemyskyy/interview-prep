# Задачи: деревья, графы, ДП

Паттерны задач на деревья, графы и динамическое программирование: DFS для проверки BST и подсчёта островов, BFS для кратчайшего пути в лабиринте и ДП от определения до Kadane, Coin Change и LCS. Узнать паттерн важнее, чем выучить конкретные задачи. Задачи на массивы и строки — на странице [Задачи: массивы и строки](leetcode-patterns.md), теория графов — в [Сортировках и графах](sorting-graphs.md).

## DFS на дереве и графе { #dfs }

### Как проверить, что дерево — валидное BST? { #validate-bst }

**Уровень:** Middle

!!! abstract "Ответ вслух"
    Рекурсивно передаём каждому узлу допустимый диапазон значений `(min, max)`. Левое поддерево получает верхнюю границу `node.val`, правое — нижнюю. Каждый узел посещается один раз, поэтому сложность — O(N).

```java
boolean isValidBST(TreeNode root) {
    return validate(root, Long.MIN_VALUE, Long.MAX_VALUE);
}

boolean validate(TreeNode node, long min, long max) {
    if (node == null) return true;
    if (node.val <= min || node.val >= max) return false;

    return validate(node.left, min, node.val) &&   // левое поддерево: все < node.val
           validate(node.right, node.val, max);     // правое поддерево: все > node.val
}
// O(N) — посещаем каждый узел один раз
```

Устройство BST и обходы деревьев — в [Big O и структуры данных → деревья](algorithms.md#tree-traversal).

!!! warning "Ловушка: сравнивать узел только с детьми"
    Проверка «левый ребёнок меньше, правый больше» пропускает такой случай: корень 5, его правый ребёнок 6, а у 6 левый ребёнок 3. Локально всё в порядке, но 3 лежит в правом поддереве корня и при этом меньше 5.

    Поэтому передают диапазон от всех предков. Границы берут `long`, чтобы узел со значением `Integer.MIN_VALUE` или `Integer.MAX_VALUE` не совпал с границей.

### Как посчитать количество островов? { #islands }

**Уровень:** Middle

!!! abstract "Ответ вслух"
    Идём по сетке; встретив непосещённую землю `'1'`, увеличиваем счётчик и DFS'ом «топим» весь остров — помечаем все связанные клетки водой. Так каждый остров засчитывается ровно один раз. Сложность — O(N×M) по времени и по памяти на стек рекурсии.

```text
Дана сетка из '1' (земля) и '0' (вода). Найти количество островов.
```

```java
int numIslands(char[][] grid) {
    int count = 0;

    for (int i = 0; i < grid.length; i++) {
        for (int j = 0; j < grid[0].length; j++) {
            if (grid[i][j] == '1') {
                dfs(grid, i, j);  // "топим" весь остров
                count++;
            }
        }
    }
    return count;
}

void dfs(char[][] grid, int r, int c) {
    if (r < 0 || r >= grid.length || c < 0 || c >= grid[0].length) return;
    if (grid[r][c] != '1') return;

    grid[r][c] = '0'; // помечаем посещённой (вместо отдельного visited)

    dfs(grid, r + 1, c);
    dfs(grid, r - 1, c);
    dfs(grid, r, c + 1);
    dfs(grid, r, c - 1);
}
// O(N×M) время и пространство (стек рекурсии)
```

!!! warning "Ловушка: глубина рекурсии на большой сетке"
    Остров на всю сетку 1000×1000 даёт до миллиона вложенных вызовов `dfs`, и стек потока переполнится. На больших входах обход переписывают итеративно — через `ArrayDeque` как стек или очередь. Ещё одна деталь: решение портит входную сетку, и об этом стоит сказать интервьюеру.

    2. Как решение обходится без отдельного `visited`?
    3. Что может пойти не так на очень большой сетке?

## BFS — кратчайший путь { #bfs }

### Как найти кратчайший путь в лабиринте? { #maze }

**Уровень:** Middle

!!! abstract "Ответ вслух"
    BFS из стартовой клетки: очередь хранит координаты и длину пути, соседи проверяются в четырёх направлениях. Так как BFS идёт слоями, первый раз, когда он достигает финиша, — это кратчайший путь. Сложность — O(N×M).

```text
Сетка 0/1, 0 — проход, 1 — стена. Найти длину кратчайшего пути из (0,0) в (n-1,m-1).
```

```java
int shortestPath(int[][] grid) {
    int n = grid.length, m = grid[0].length;
    if (grid[0][0] == 1 || grid[n-1][m-1] == 1) return -1;

    Queue<int[]> queue = new ArrayDeque<>();
    queue.offer(new int[]{0, 0, 1}); // row, col, path_length
    grid[0][0] = 1; // помечаем посещённой

    int[][] dirs = {{0,1},{0,-1},{1,0},{-1,0}};

    while (!queue.isEmpty()) {
        int[] curr = queue.poll();
        int r = curr[0], c = curr[1], dist = curr[2];

        if (r == n - 1 && c == m - 1) return dist;

        for (int[] d : dirs) {
            int nr = r + d[0], nc = c + d[1];
            if (nr >= 0 && nr < n && nc >= 0 && nc < m && grid[nr][nc] == 0) {
                grid[nr][nc] = 1; // помечаем
                queue.offer(new int[]{nr, nc, dist + 1});
            }
        }
    }
    return -1;
}
// O(N×M)
```

BFS по графу в общем виде — в [Сортировки и графы → BFS](sorting-graphs.md#graph-bfs).

!!! warning "Ловушка: DFS для кратчайшего пути"
    DFS находит какой-то путь, но не обязательно кратчайший — он уходит в глубину по первой попавшейся ветке. Для кратчайшего пути в сетке или невзвешенном графе нужен BFS.

## Динамическое программирование { #dp }

### Что такое динамическое программирование? { #dp-basics }

**Уровень:** Middle

=== "Коротко"

    !!! abstract "Ответ вслух"
        Задачу разбивают на подзадачи и сохраняют их результаты, чтобы не пересчитывать. Сверху вниз (top-down) — рекурсия с мемоизацией, снизу вверх (bottom-up) — заполнение таблицы от маленьких подзадач к большим. Сигналы в условии: «максимум или минимум», «количество способов», «подпоследовательность».

=== "Подробно"

    **Fibonacci с мемоизацией (top-down):**

    ```java
    // Классика: Fibonacci с мемоизацией (top-down)
    Map<Integer, Long> memo = new HashMap<>();

    long fib(int n) {
        if (n <= 1) return n;
        if (memo.containsKey(n)) return memo.get(n);
        long result = fib(n - 1) + fib(n - 2);
        memo.put(n, result);
        return result;
    }
    ```

    **Fibonacci с табуляцией (bottom-up)** — таблица на O(N) памяти сворачивается до двух переменных, O(1):

    ```java
    // Fibonacci с табуляцией (bottom-up, O(N) память → можно O(1))
    long fibDP(int n) {
        if (n <= 1) return n;
        long prev2 = 0, prev1 = 1;
        for (int i = 2; i <= n; i++) {
            long curr = prev1 + prev2;
            prev2 = prev1;
            prev1 = curr;
        }
        return prev1;
    }
    ```

    **Задача о рюкзаке (0/1 Knapsack)** — `dp[i][w]` — лучшая стоимость из первых `i` предметов при вместимости `w`:

    ```java
    // Задача о рюкзаке (0/1 Knapsack)
    int knapsack(int[] weights, int[] values, int capacity) {
        int n = weights.length;
        int[][] dp = new int[n + 1][capacity + 1];

        for (int i = 1; i <= n; i++) {
            for (int w = 0; w <= capacity; w++) {
                dp[i][w] = dp[i-1][w]; // не берём предмет i
                if (weights[i-1] <= w) {
                    dp[i][w] = Math.max(dp[i][w],
                        dp[i-1][w - weights[i-1]] + values[i-1]); // берём
                }
            }
        }
        return dp[n][capacity];
    }
    ```

!!! warning "Ловушка: рекурсия без мемоизации"
    Наивный `fib(n - 1) + fib(n - 2)` без кэша пересчитывает одни и те же подзадачи и работает за O(2^N). Мемоизация сводит это к O(N). Но рекурсия top-down по-прежнему тратит O(N) стека, поэтому для больших N берут bottom-up.

??? question "Проверь себя"

    2. Почему Fibonacci без мемоизации — O(2^N)?
    3. Что означает `dp[i][w]` в задаче о рюкзаке?

### Как найти подмассив с максимальной суммой (Kadane)? { #kadane }

**Уровень:** Middle

!!! abstract "Ответ вслух"
    Для каждой позиции решаем: продолжить текущий подмассив или начать новый с текущего элемента — берём большее из `nums[i]` и `currentSum + nums[i]`. Попутно запоминаем лучший результат. Это ДП без таблицы: O(N) времени и O(1) памяти.

```text
Input: [-2, 1, -3, 4, -1, 2, 1, -5, 4]
Output: 6  (подмассив [4, -1, 2, 1])
```

```java
int maxSubArray(int[] nums) {
    int maxSum = nums[0];
    int currentSum = nums[0];

    for (int i = 1; i < nums.length; i++) {
        // Либо расширяем текущий подмассив, либо начинаем новый с текущего элемента
        currentSum = Math.max(nums[i], currentSum + nums[i]);
        maxSum = Math.max(maxSum, currentSum);
    }
    return maxSum;
}
// O(N) время, O(1) память — классика DP без таблицы
```

!!! warning "Ловушка: начинать с нуля"
    Если инициализировать `maxSum = 0`, на массиве из одних отрицательных чисел ответ будет 0 — сумма пустого подмассива, хотя он не разрешён. Поэтому стартуют с `nums[0]`.

### Как набрать сумму минимальным числом монет (Coin Change)? { #coin-change }

**Уровень:** Middle

!!! abstract "Ответ вслух"
    `dp[i]` — минимальное число монет для суммы `i`, и `dp[i] = min(dp[i - coin] + 1)` по всем монетам. Заполняем от 0 до `amount`, начальное значение `amount + 1` играет роль бесконечности. Сложность — O(amount × coins) времени и O(amount) памяти.

```text
Монеты [1, 5, 6, 9], сумма = 11. Минимальное количество монет.
Output: 2  (5 + 6)
```

```java
int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1); // "бесконечность"
    dp[0] = 0;

    for (int i = 1; i <= amount; i++) {
        for (int coin : coins) {
            if (coin <= i) {
                dp[i] = Math.min(dp[i], dp[i - coin] + 1);
            }
        }
    }
    return dp[amount] > amount ? -1 : dp[amount];
}
// O(amount × coins) время, O(amount) память
```

!!! warning "Ловушка: жадный алгоритм"
    Брать каждый раз самую крупную монету кажется естественным, но на этом примере жадность даёт 9 + 1 + 1 — три монеты, а оптимум — 5 + 6, две. Жадный выбор работает только для «удобных» наборов монет, поэтому в общем случае нужно ДП.

### Как найти наибольшую общую подпоследовательность (LCS)? { #lcs }

**Уровень:** Middle

!!! abstract "Ответ вслух"
    `dp[i][j]` — длина LCS для первых `i` символов первой строки и первых `j` второй. Если символы совпали, берём `dp[i-1][j-1] + 1`, иначе — максимум из `dp[i-1][j]` и `dp[i][j-1]`. Сложность — O(M×N) по времени и памяти.

```text
Input: s1 = "abcde", s2 = "ace"
Output: 3  ("ace")
```

```java
int longestCommonSubsequence(String s1, String s2) {
    int m = s1.length(), n = s2.length();
    int[][] dp = new int[m + 1][n + 1];

    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (s1.charAt(i - 1) == s2.charAt(j - 1)) {
                dp[i][j] = dp[i-1][j-1] + 1;        // символы совпали
            } else {
                dp[i][j] = Math.max(dp[i-1][j], dp[i][j-1]); // берём лучший из двух
            }
        }
    }
    return dp[m][n];
}
// O(M×N) время и память
```

!!! warning "Ловушка: подпоследовательность ≠ подстрока"
    Подпоследовательность не обязана быть непрерывной: `"ace"` — подпоследовательность `"abcde"`, но не подстрока. Для общей подстроки при несовпадении символов `dp[i][j]` обнуляют, а не берут максимум соседей.
