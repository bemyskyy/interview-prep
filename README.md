# Interview Prep — База знаний для технических собеседований

Открытая база знаний для подготовки к техническим собеседованиям по Java и backend-разработке. Написана на русском языке.

Не определения ради галочки, а разбор **с кодом, ловушками с реальных собесов и объяснением почему это работает именно так**.

🔗 **Сайт:** https://bemyskyy.github.io/interview-prep/

---

## Что внутри

| Раздел | Темы |
|---|---|
| **Java** | JVM и память, многопоточность, ООП, коллекции, исключения, дженерики, Stream API, IO/NIO, SOLID, паттерны |
| **Spring** | Core (IoC/DI/AOP), Spring Boot, MVC/REST, Data JPA, Security, тестирование |
| **Данные** | SQL, ACID, MVCC, индексы, оконные функции, NoSQL, CAP-теорема, Redis, Cassandra |
| **Kafka** | Партиции, оффсеты, consumer groups, rebalancing, ISR, acks, семантики доставки, DLQ |
| **Computer Science** | Алгоритмы, Big O, структуры данных, сортировки, графы, паттерны LeetCode, сети (HTTP/TCP/TLS/gRPC) |
| **Проектирование** | Системный дизайн, масштабирование, кэширование, очереди, DDD, микросервисы, CQRS, Docker, CI/CD, K8s |

Каждая страница построена одинаково: **суть → код или схема → ловушки на собесах → итоговая шпаргалка** для быстрого повторения перед звонком.

## Технологии

Сайт собран на [MkDocs](https://www.mkdocs.org/) с темой [Material for MkDocs](https://squidfunk.github.io/mkdocs-material/). Контент — обычный Markdown, поэтому дополнять его может любой, кто умеет писать текст.

## Запуск локально

Нужен установленный Python 3.

```bash
# 1. Клонировать репозиторий
git clone https://github.com/bemyskyy/interview-prep.git
cd interview-prep

# 2. Установить зависимости
pip install mkdocs-material

# 3. Запустить локальный сервер с live-reload
mkdocs serve

# Открыть в браузере http://127.0.0.1:8000
```

Страницы обновляются автоматически при сохранении файлов.

## Как внести вклад

Проект открытый и живёт за счёт сообщества. Помочь можно по-разному:

- **Нашёл ошибку или неточность** — открой [issue](https://github.com/bemyskyy/interview-prep/issues) или сразу присылай pull request.
- **Знаешь тему глубже** — дополни существующую страницу.
- **Завалили вопросом, которого здесь нет** — добавь его разбор.
- **Хочешь новый раздел** — предложи в issue, обсудим.

### Как отправить pull request

Если раньше не работал с pull request — это проще, чем кажется:

```bash
# 1. Сделай форк репозитория (кнопка Fork вверху страницы на GitHub)

# 2. Клонируй свой форк
git clone https://github.com/ТВОЙ_ЛОГИН/interview-prep.git
cd interview-prep

# 3. Создай ветку для своих изменений
git checkout -b add-my-topic

# 4. Внеси правки в нужные .md файлы, проверь локально через mkdocs serve

# 5. Закоммить и запушь
git add .
git commit -m "Добавил разбор темы X"
git push origin add-my-topic

# 6. На GitHub нажми "Compare & pull request"
```

Не разобрался — напиши в комментариях под постом или в issue, помогу.

### Стиль оформления страниц

Чтобы контент был единообразным, придерживайся структуры существующих страниц:

- Объясняй **почему**, а не только **что**. Определение без понимания бесполезно на собесе.
- Код примеров — на Java, с комментариями что происходит.
- Ловушки и частые вопросы оформляй через блоки `!!! warning` / `!!! tip`.
- В конце страницы — таблица-шпаргалка с ключевыми выводами.
